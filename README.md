# 童声配音台

个人使用的 Windows 本地工具：浏览器界面、Python 处理服务、SQLite 任务记录。视频留在本机；台词改写会发送给你配置的文本 API。

## 当前交付状态

`v1.0` 是源码和本机流程的里程碑，不是对所有儿童视频的自动质量保证。已有一段约两分钟真实视频生成候选 MP4，任务状态为 `completed_with_warnings`；歌曲、角色对应、对白残留和音画同步仍需逐片核听。界面里的“服务已配置”仅表示依赖可用，不代表实际推理或最终成片质量验收通过。

## 启动

1. 启动 Docker Desktop，确认现有 `omnivoice` 与 `faster-whisper-api` 容器正常。
2. 首次准备界面与后端环境时，运行 `launcher/首次安装.bat`。它需要本机 Python、Node.js、FFmpeg；模型运行时与权重是另一组依赖，不应把后端安装成功等同于模型安装完成。
3. 运行 `launcher/启动童声配音台.bat`，访问 `http://127.0.0.1:8787`。
4. 新建系列、选择目标语言和 L1–L5 档位，填写视频完整本地路径。默认不覆盖、不移动原视频。
5. 处理任务会按阶段保存缓存；遇到阻断异常时查看异常说明，不要反复强制从头处理。

`launcher/停止童声配音台.bat` 只用于停止本工具服务，不用于关闭 Docker 或其他应用。处理视频期间不要强行关闭电脑。

## 本机对接

- 转写：`http://127.0.0.1:8001`，复用 faster-whisper / Speaches。
- 音色与配音：`http://127.0.0.1:7861`，复用 OmniVoice。
- 文本 API：读取项目根目录的 `.env`，或通过环境变量/本地 `.env` 中的 `DUBBING_ENV_FILE` 指定外部配置路径。参照 `.env.example` 配置；工具不修改外部配置，密钥不能放到前端或提交到代码仓库。
- 项目缓存、数据库：`work/`。真实分离与声纹运行时：`work/model-runtime/`；BandIt 权重：`work/models/`。

## 处理规则

- 简化后的最终文本同时供配音和字幕使用；字幕只显示目标语言。
- 语言等级和目标语速一起影响台词长度，实际合成后再次测量时长，不能靠截掉单词或音频来对齐。
- 原歌曲保留原音频；检测不确定时需显示异常，不能把“未运行歌曲检测”当成“没有歌曲”。
- 角色参考以主样本和备用样本为目标；跨集匹配必须依据真实声纹，不能把每集随机说话人编号当作固定角色。
- L1–L5 是工具的简化档位，不是 CEFR、HSK 或识字考试认证。音色相似度、语义保真与分离残留仍有质量边界。

## 开发与验收

前端在 `frontend/`，后端在 `backend/app/`。代码结构与处理流程见 [架构设计](docs/ARCHITECTURE.md)，环境准备、数据迁移与验收层级见 [本地运行与验收](docs/OPERATIONS.md)，接口边界见 [API 契约](docs/API_CONTRACT.md)。全量后端测试使用包含 NumPy、PyTorch 等模型依赖的 `work/model-runtime/venv/Scripts/python.exe -m pytest tests`；前端测试和构建在 `frontend/` 中执行 `npm test` 与 `npm run build`。

本地验收记录、试片、音色、模型与运行缓存不随源码发布。通过编译、健康检查或合成信号测试，均不等于真实成片已验收。
