# 分阶段人工确认：需求与 UI/UX 设计

状态：需求与 UI/UX 设计、实现及自动化验收已完成；不改变现有媒体处理算法。

## 目标

用户希望每完成一项处理，就能检查该项结果并亲自确认，确认后才开始下一项。确认必须由后端执行并持久保存，不能只是把前端按钮设为禁用。重启或刷新后应回到同一个待确认阶段；异常要明确阻断或作为待接受警告呈现。

沿用当前本地工具的视觉风格和 10 阶段顺序，不引入新的处理平台或自动跳过确认的设置。每一关默认都等待用户确认。

## 处理阶段与确认内容

| 顺序 | 阶段 | 完成后应供用户检查 | 继续条件 |
| --- | --- | --- | --- |
| 1 | 检查媒体 | 文件名、时长、视频/音频轨道和可播放预览 | 媒体探测成功；用户确认源片正确 |
| 2 | 分离对白 | 对白轨与背景轨试听；歌曲区间及分离服务警告 | 必要分离产物有效；阻断异常已解决 |
| 3 | 句级转写 | 按时间排序的原文、时间窗、歌曲/对白类型；可编辑识别错误 | 转写记录有效；用户确认原文与分类 |
| 4 | 角色聚类 | 说话人分组及对应台词；突出低置信度/碎片化异常 | 每条对白的角色归属已检查；阻断异常已解决 |
| 5 | 准备音色 | 角色名、样本试听、音色档案与映射状态 | 对白角色均有可用映射；用户确认角色/音色关系 |
| 6 | 按等级改写 | 原文与目标文对照、目标语言/等级、可编辑目标文本 | 目标文本非空；异常已处理；用户确认语义与难度 |
| 7 | 逐句配音 | 逐句试听、音色、实际时长与原时间窗差异 | 必需对白音频有效；截断、超窗等阻断异常已解决 |
| 8 | 混音 | 混音候选试听；背景音乐、音效、原歌曲保留情况 | 混音产物有效；没有未解决阻断异常 |
| 9 | 生成字幕 | 目标语言字幕预览及时间点；字幕与目标台词一致 | 字幕文件有效；用户确认字幕显示 |
| 10 | 输出 MP4 | 候选视频预览、文件信息、导出检查结果 | 导出文件有效；用户最终验收后项目才标记完成 |

非阻断警告不得隐藏，也不得默认视作用户接受。确认面板必须列出警告；用户可在查看后继续确认。阻断异常不能通过阶段确认绕过，必须先解决并由相应阶段复核。歌曲按现有约定保留原音频；若歌曲检测能力不可用，界面应明示未验证，不得显示为“已确认无歌曲”。

## UI/UX

### 主进度区

- 保留现有项目卡、阶段顺序、品牌颜色和异常摘要。
- 阶段状态统一为“未开始 / 处理中 / 待你确认 / 已确认 / 需处理”。完成计算本身不等于已确认。
- 顶部突出当前待审阶段；之前已确认阶段可展开查看，之后阶段保持锁定。异常摘要显示阻断数和警告数，并可直接打开异常列表。
- 刷新或重进项目后，根据后端状态恢复当前关卡，并突出提示“结果已保存，等待确认”。

### 桌面端低保真布局

以用户提供的当前项目截图为基线：保留项目摘要、横向十步进度线、右上任务操作和异常提示条；在异常提示条下新增阶段结果检查卡。窄窗口时阶段进度可横向滚动，检查卡上下堆叠。

```text
┌───────────────────────────────────────────────────────────────────────┐
│ 当前项目：小火车联盟 · 真实联调       待你确认：句级转写   查看异常 │
│ 文件名 · 时长 · 处理说明                                  [暂停/继续] │
├───────────────────────────────────────────────────────────────────────┤
│ ✓检查 ─ ✓分离 ─ ●转写 ─ 🔒角色 ─ 🔒音色 ─ 🔒改写 ─ 🔒配音 ─ … ─ 🔒输出 │
├───────────────────────────────────────────────────────────────────────┤
│ ⚠ 需要处理 2 项（若有阻断异常，显示“先处理后确认”）                    │
├───────────────────────────────────────┬───────────────────────────────┤
│ ③ 句级转写 · 已完成 · 待你确认        │ 本关检查                      │
│ 片段时间   角色      原文              │ 片段 25 条                    │
│ 00:12-00:14   —      ...               │ 阻断异常 0 · 警告 1            │
│ 00:15-00:17   —      ...               │ [查看异常]                    │
│ [试听] [编辑本句]                      │                               │
│                                       │                               │
├───────────────────────────────────────┴───────────────────────────────┤
│ 已保存。检查本阶段结果后再继续。 [重新处理本阶段] [确认并进入下一步 →] │
└───────────────────────────────────────────────────────────────────────┘
```

“✓”只代表用户确认过；“●”代表当前关；“🔒”代表尚未解锁。任务处理中显示当前阶段百分比，但只有产物完成时才显示“待你确认”。阻断时主按钮替换为禁用态说明和“前往处理异常”，不可通过键盘快捷操作绕过。

### 阶段检查卡

1. 标题区显示阶段编号、名称、状态、耗时/进度和简短说明。
2. 结果区呈现可检查的实际产物；若尚无预览或数据，显示真实原因，不能以示例数据代替。
3. 操作区提供“确认并进入下一步”主按钮，以及适用时的“编辑结果”“重新处理本阶段”次操作。
4. 主按钮仅在阶段任务结束、产物有效且无未解决阻断项时启用。点击后显示正在保存确认/启动下一阶段，避免重复提交。
5. 重新处理当前阶段需说明当前阶段及其下游产物会失效；不覆盖或删除源视频。回改更早阶段时，明确列出会重新生成的下游阶段。
6. 第 10 阶段完成后按钮文案为“确认成片并完成”，只有最终确认后才显示“已完成”；候选 MP4 与“已验收成片”应明确区分。

### 视觉与适配

- 在当前浅色卡片、蓝色主色和圆角面板系统内扩展，不重做整套视觉语言。
- 桌面端沿用截图中的水平阶段线；阶段结果与异常摘要采用主内容+窄侧栏，窗口较窄时改为上下堆叠。
- 主确认操作固定在结果卡底部，长列表滚动时仍可见；阻断状态使用文字+图标而不只依赖颜色。
- 所有操作可键盘访问；状态变化通过可访问的提示区播报，避免确认成功仅靠动画表达。

## 行为与持久化约束

- **权威状态**：沿用项目 `checkpoint_json` 存 `pending_confirmation_stage`、有效 `confirmed_stages`、按阶段递增的 `stage_revisions`、以及追加式 `confirmation_history`；项目和当前 job 的 `status` 作为其可查询镜像。无需新增 SQLite 列；旧项目已有 `completed_stages` 只证明处理过，不证明人工确认过。
- **API**：`GET /api/projects/{id}` 返回上述确认字段。新增 `POST /api/projects/{id}/stages/{stage}/confirm`；非末阶段接受当前阶段和版本，最终 `export` 阶段还需传候选 `output_sha256`。确认响应返回新状态及下一阶段。阶段不匹配/版本过期/产物无效返回 409；阻断异常未解决返回 409 和异常 ID；重复同版本确认作为幂等成功返回，不重复排队。
- 阶段完成后，后端将项目与任务置为 `awaiting_confirmation`，写入 pending 阶段和修订号，保留完成 checkpoint，并立即停止执行；不自动开始下一阶段。worker 每个阶段边界都检查 pending gate。确认非末阶段后，同一个 job 在事务中清除 pending 并改为 queued；提交后才通知 worker，从已完成 checkpoint 接续。最后阶段确认时校验源 SHA、候选文件存在且 SHA 匹配，只记录所验收的候选版本并标记完成。
- **原子与恢复**：阶段 checkpoint、pending 阶段、项目状态和 job 状态在同一 SQLite 事务提交。启动时只恢复真正中断的 `running` job；`awaiting_confirmation` 保持停靠，不进入 queued。条件更新以项目 pending 阶段与 revision 做 compare-and-swap，确认历史、状态清除和重排入队一次提交，避免双击或并发确认推进两次。
- **旧数据**：旧 checkpoint 没有确认历史时，不能补写“已确认”。下次继续任务会从最早一个已完成但尚未确认的阶段开始逐关复核；已生成的媒体可预览，不会因此自动重跑或导出为已验收成片。
- **入口防绕过**：常规 enqueue、兼容 enqueue、重试和 `force` 不能跳过当前 pending；待确认时仅允许“确认当前阶段”或“重新处理当前阶段”。句级重生成不得在后台自带混音/字幕/导出；它必须撤销配音及下游确认，回到配音关，确认后再逐关推进。
- **编辑/回退**：运行中的项目拒绝并发修改。支持的变更映射固定为：`speaker_key`/角色音色映射→角色/音色阶段；`target_text`→改写阶段；`speed`/句级音频→配音阶段；导入分离轨→分离阶段；歌曲区间→转写阶段。当前关卡可直接修改后复核；改已确认的较早阶段时，保留历史但将该阶段及所有下游确认标为失效、清除相应 checkpoint/缓存，并从该阶段重新处理。UI 必须先展示失效范围，避免安静地沿用旧结果。
- **异常**：阻断异常只有在重新运行所属阶段、阶段级质量检查通过且异常被解决后才允许确认；单独把 anomaly 的 `resolved` 标志改真不能直接解锁。确认只受当前及前序阶段的阻断影响，避免后续错误锁死旧结果复核。非阻断警告按阶段显示并只需接受一次；阶段回改导致确认失效时，再次复核需重新接受。
- **候选与下载**：生成候选 MP4 是 `export` 阶段的产物，不代表已验收。最终确认前允许在本地播放器预览候选；`POST /api/projects/{id}/export` 的正式下载/完成响应只对已确认的候选开放，且响应/确认历史绑定其 SHA-256。
- **阶段预览**：检查卡读取真实阶段产物。对白/背景/音乐/音效轨和混音轨需有本地只读试听地址；角色样本、句级音频和字幕复用项目已有媒体地址或增加只读地址。缺失产物展示具体状态与异常，不填入演示内容。
- **失效最小化**：`probe → separate → transcribe → diarize → characters → rewrite → synthesize → mix → subtitle → export`。回退任一阶段只重跑该阶段及右侧依赖阶段，不覆盖源视频；确认历史用 `valid/invalidated_at/reason` 表示，不能物理删除审计记录。

## 验收标准

1. 任一成功阶段结束后，队列停在 `awaiting_confirmation`；下一阶段未运行，项目 API 明确返回待确认阶段。
2. 用户确认当前阶段后只启动下一阶段；重复点击/并发确认幂等且只推进一次；确认其他阶段或陈旧 revision 返回冲突且不改变状态。
3. 未解决阻断异常或无效/缺失阶段产物时，后端拒绝确认；非阻断警告在确认界面可见。
4. 服务重启后仍停在原阶段、确认历史和产物仍可查；不会自行继续。升级前留下的阶段缓存逐关显示待确认，而不是回填为已确认。
5. 编辑或重新处理本阶段会清除本阶段及下游确认，且源文件不变；向前回退的失效范围明确。
6. 第 10 阶段结果只有用户最终确认后才成为项目完成状态。
7. 前端覆盖待确认、处理中、阻断、警告、离线/接口失败、恢复后待确认等状态；主按钮状态与后端响应一致。
8. 通过自动化测试后，再在现有本地浏览器中检查排版和真实待确认/阻断状态。真实儿童视频全流程验收仍需另行确认真实媒体产物，不以 UI 或模拟数据替代。

## 实施边界

本次仅实现阶段停靠、人工确认、阶段状态展示与必要 API/测试/文档；不改变 ASR、分离、说话人识别、改写、音色创建、混音算法或歌曲判定能力，也不将当前被阻断的真实试片标为成功。
