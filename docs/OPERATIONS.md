# 本地运行与验收

## 安装边界

本仓库只包含源码和测试。`.env`、`work/`、`outputs/`、模型权重、数据库、生成视频和前端构建产物均不进入 Git；换机器或重新克隆后，需要在本机重新配置或从可信备份恢复。不要把 API 密钥、Hugging Face 令牌、儿童原片、角色声纹或音色样本提交到公开仓库。

Windows 本地依赖为 Python 3.11+、Node.js、FFmpeg/ffprobe；转写服务默认在 `127.0.0.1:8001`，OmniVoice 默认在 `127.0.0.1:7861`。BandIt、歌曲检测和 Community-1 各自需要项目 `work/model-runtime/` 下的模型运行环境及权重。文本 API 的非公开设置放在本机 `.env` 或由 `DUBBING_ENV_FILE` 指向的外部配置中；参照 `.env.example`，不要把密钥填在浏览器界面。

首次安装运行 `launcher/首次安装.bat`，它安装基础后端依赖并构建前端，不负责下载全部模型权重。日常启动运行 `launcher/启动童声配音台.bat`，默认监听 `127.0.0.1:8787`；该端口已有其他项目实例时，启动器会拒绝复用该进程。关闭时使用同目录的停止脚本，它只停止经路径与命令行核实的本项目进程。

## 数据与恢复

项目根目录可移动，但 Python 虚拟环境和数据库里的媒体路径不能假定自动可移植。迁移时先确认没有运行任务，再复制模型、缓存与项目文件；用 SQLite 在线备份复制 `work/dubbing.sqlite3`，仅在副本中把旧项目根目录的绝对路径改成新根目录。源视频位于项目外时保留其原路径；迁移后逐项检查模型环境、项目预览与候选成片。不要复制旧的 `work/runtime/backend.pid` 或 `work/dubbing.worker.lock` 作为新实例的运行状态。

处理结果按阶段保存在 `work/projects/`；重启后可从 checkpoint 恢复。修正某句台词会使该句配音及下游混音、字幕、导出失效，不应复用旧成片。原片只读，导出始终是另一个文件。歌曲区间保留原音频，未能可靠识别的歌唱、角色、时长或分离残留必须作为异常呈现。

## 验收层级

1. 在已装模型依赖的环境中运行 `work/model-runtime/venv/Scripts/python.exe -m pytest tests`，并在 `frontend` 中运行 `npm test` 与 `npm run build`。仅安装 `pyproject.toml` 的基础/测试依赖不包含 NumPy、PyTorch 等模型依赖，不能据此宣称全量后端测试通过。
2. `/api/health` 与 `/tts/ping` 只验证服务可达，不证明真实转写、模型推理或配音质量。
3. 用真实短片验证句级 ASR、歌曲区间、说话人分组与跨集角色、参考样本、目标语言改写、实测 TTS 时长、背景混音、字幕和完整 MP4。
4. 最终人工试听重点检查原对白残留、角色串音、歌曲被改写、语速异常、音画错位及字幕一致性。候选片显示 `completed_with_warnings` 时不等同于儿童观看版已通过质量验收。

`v1.0` 是可复现的代码里程碑标签，不表示所有真实视频都能零人工、无瑕疵成片。
